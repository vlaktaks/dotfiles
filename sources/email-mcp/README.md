# Email MCP — Outlook + Proton Mail for OpenCode

On-demand, manual-only email access for OpenCode on Omarchy/Arch Linux. One small,
stdlib-only MCP server (`email-mcp`) provides the same tool set for both accounts:

- **Outlook** (personal Outlook.com or Microsoft 365): Microsoft Graph with delegated
  OAuth permissions via **device-code** login. You never type your Microsoft password
  anywhere except Microsoft's own sign-in page.
- **Proton Mail**: the official **Proton Mail Bridge** (Arch `extra` repo) accessed
  locally over IMAP/SMTP with the Bridge-generated password (never your Proton password),
  TLS pinned to the Bridge's own certificate, loopback only.

The server is **disabled by default** in OpenCode (`disabled: true`) and is connected
manually via `/mcps` when you want to work with email. Nothing downloads, reads,
modifies, or deletes email when OpenCode starts.

## Architecture

```
OpenCode (turned on)              -- nothing runs, no mail access
  └─ /mcps -> connect "email-mcp" -- starts: email-mcp (stdio, stdlib Python)
       ├─ Outlook tools  -> Microsoft Graph HTTPS (OAuth device-code tokens on disk, 0600)
       └─ Proton tools   -> 127.0.0.1:1143/1025 Proton Mail Bridge (spawned on first use)
                            Bridge stops via the email_shutdown tool or when email-mcp exits
```

Secrets live in `~/.config/opencode/secrets/` (dir `0700`, files `0600`), outside the
dotfiles repository:

| File | Contents |
| --- | --- |
| `outlook-config.json` | Azure app client ID + tenant (client ID is public, still kept local) |
| `outlook-tokens.json` | OAuth access + refresh tokens |
| `proton-credentials.json` | Bridge IMAP/SMTP username + Bridge-generated password |

## Safety model (enforced, not just documented)

| Layer | What it enforces |
| --- | --- |
| Server disabled in config | OpenCode start never launches the server |
| Read/write tool split | `list_*`, `search_*`, `read_*`, `email_accounts` are read-only |
| In-code hard gates | `send_draft` requires `confirm: true`; `move_to_folder` requires `confirm: true` and reports exact counts; `delete_permanently` requires the literal string `PERMANENTLY DELETE`; bulk capped at 100 messages |
| OpenCode `ask` permissions | Every write tool (`draft_new`, `draft_reply`, `send_draft`, `move_to_folder`, `delete_permanently`) prompts you in OpenCode before executing — you see the exact arguments (draft body, message ids) and must approve |
| Draft-then-send | Nothing can be sent without first existing as a draft; `send_draft` sends only the stored draft |
| Trash over delete | `delete_permanently` is separate; everything else uses folders you can recover from |
| Attachments | Listed (name/size/type) but never downloaded or executed |
| Email content | Treated as untrusted data; the model never executes commands from mail bodies |

## Setup — one time

### 0. Install the integration (already part of the dotfiles installer)

```bash
./install/install.sh        # runs install/email.sh among the other steps
./install/verify.sh         # checks config, gates, permissions, secret hygiene
```

Or just the email step: `bash install/email.sh ~/.dotfiles`

### 1. Proton Mail Bridge

```bash
sudo pacman -S protonmail-bridge
```

- The Bridge is in Arch's **official `extra` repository** (GPL-3, built and signed by
  the Arch maintainers; pacman verifies the signature via archlinux-keyring).
- **Requires a paid Proton plan.** If your plan does not include Bridge, IMAP login
  will fail with a clear error; nothing else changes.
- The package ships a systemd **user** unit but it is **not enabled** by default and
  this installer never enables it. `email-mcp` starts the Bridge itself on first use
  and stops it on `email_shutdown`.
- The Bridge needs a Secret Service (GNOME Keyring works; `secret-tool` is the probe).

Run the Bridge GUI once and add your Proton account:

```bash
protonmail-bridge          # GUI: click "Add account", sign in on proton.me (your browser)
```

Then in the GUI, open your account settings and copy the **Bridge IMAP/SMTP password**
(it is generated by the Bridge for your local client; it is not your Proton password).
Give it to the integration with (input is not echoed, stored 0600):

```bash
email-mcp login proton    # asks for Proton address + Bridge password, then verifies the connection
```

### 2. Outlook (Microsoft Graph, device-code login)

You need a **free Azure app registration** (public client, no secret). One time, ~3 minutes:

1. Open https://entra.microsoft.com (or https://portal.azure.com) with the Microsoft
   account you use for this mailbox.
2. **Identity → Applications → App registrations → New registration**
   - Name: `email-mcp` (anything you like)
   - Supported account types: **Personal Microsoft accounts only** (for Outlook.com)
     — or the appropriate tenant option for Microsoft 365 work/school.
   - Redirect URI: platform **Mobile and desktop applications**, URI `http://localhost`
     (device-code flow does not use it; the portal requires a value).
3. Open the registration → **Authentication → Advanced settings → Allow public client
   flows: Yes** → Save.
4. Copy the **Application (client) ID** from the Overview page.

Then sign in (device code; the password goes to Microsoft only, in your browser):

```bash
email-mcp login outlook
# paste the client ID, keep the default tenant "consumers" for personal accounts
# open the printed URL in your browser, enter the printed code, sign in, press Enter here
```

Permissions are incremental by design:

- `email-mcp login outlook` requests only `offline_access Mail.Read` (+ identity info
  for labeling) — read/search/draft access. Note: creating drafts requires
  `Mail.ReadWrite`, so this minimal login is read-only in practice.
- `email-mcp login outlook --write` additionally requests `Mail.ReadWrite` (needed for
  drafts, sending, moving, deleting). Run it when you actually want write access.

No Microsoft client secret is used or stored anywhere. Tokens are refreshed
automatically and re-stored with 0600 permissions.

### 3. Connect in OpenCode

In an OpenCode session, open `/mcps` and connect **email-mcp**. Disconnect it there
when you are done. Connecting again later is instant; nothing else runs meanwhile.

Check state any time (never prints secrets):

```bash
email-mcp status
```

## Usage examples (natural language in OpenCode)

- "Show my 10 newest emails across both accounts."
- "Summarize my unread Outlook emails."
- "Show spam messages in Proton Mail."
- "Draft a reply to this message." (you approve the `draft_reply` call, review the draft)
- "Send this approved reply." (you approve the `send_draft` call — two approvals in total)
- "Move these selected spam messages to Trash." (you approve the move; ids and count are shown)

Every result is labeled with the account it came from (`outlook` / `proton`).

## Disconnecting an account

```bash
email-mcp revoke outlook
# then revoke Microsoft consent (the real revocation):
#   personal:  https://account.live.com/consent/Manage  (remove the email-mcp app)
#   work/school: Entra "My Sign-ins" or delete the app registration

email-mcp revoke proton
# then remove the account in the Bridge GUI and optionally: sudo pacman -R protonmail-bridge
```

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `Bridge IMAP login failed ... no account yet` | Run `protonmail-bridge` GUI, add the account, re-run `email-mcp login proton` |
| `Bridge started but IMAP port did not open` | The Bridge needs a Secret Service; ensure GNOME Keyring (`secret-tool` works), then retry |
| `Could not find the Bridge TLS certificate` | Bridge GUI → Settings → Advanced → Export TLS certificate; set `EMAIL_BRIDGE_CERT=/path/to/cert.pem` in the environment (e.g. in the MCP server's `environment` in `~/.config/opencode/opencode.json`) |
| `Outlook not signed in` | `email-mcp login outlook` |
| `Outlook token refresh failed` | Consent was probably revoked; run `email-mcp login outlook` again |
| Outlook drafts fail with insufficient privileges | Run `email-mcp login outlook --write` (adds `Mail.ReadWrite`) |
| Write tool is denied in OpenCode | Expected: you must approve the prompt (the `ask` permission). "Always allow" is possible but weakens the gate |
| Spam folder missing on Proton | `list_spam` reports the available folders; Proton may not expose Junk until first use |

## Known limitations

- Proton draft ids are `drafts:<uid>@<uidvalidity>`; they go stale if the Bridge
  resets its index — re-find drafts with `list_messages(folder="drafts")`.
- Proton threading walks at most 10 reference Message-IDs and 50 messages (normal
  threads are far smaller); Outlook threading uses native Graph conversations.
- A sent Proton draft is moved to Trash (standard client behaviour) rather than deleted.
- Sending requires the Bridge to be running; it is started automatically and stopped
  by `email_shutdown`.
- `email-mcp login proton` stores the Bridge password in a 0600 file; the Bridge
  itself keeps its own secrets in the OS keyring, untouched by this integration.

## Security review notes

- `sources/email-mcp/email_mcp.py` is stdlib-only (~900 lines); `selfcheck` covers the
  hard gates, builders, and parsing without network access.
- TLS to the Bridge uses `ssl.create_default_context(cafile=<bridge cert>)`; global
  verification is never disabled. SMTP tries STARTTLS, falls back to implicit TLS.
- Graph scopes: `Mail.Read` (+`Mail.ReadWrite` only via explicit `--write` login).
  No application permissions, no shared-mailbox scopes, no client secret.
- The Bridge binds to 127.0.0.1 by default; nothing here re-exposes it.
